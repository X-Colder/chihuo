# Chihuo 生产化排期

基线日期：2026-09-02。该排期按工作日执行，真实微信支付、AppID、备案域名和云资源需要在对应阶段前准备。

## 阶段 0：发布基线

**2026-09-03 至 2026-09-04**

- 冻结当前 API 契约和数据库迁移版本。
- 建立 staging 环境、外部 Secret 管理和镜像仓库。
- 确认小程序 AppID、request 合法域名、HTTPS 证书。
- 维护回滚版本和数据库备份策略。

验收：

- staging 可重复部署。
- API、PostgreSQL、Redis 健康检查通过。
- Secret 不出现在仓库、镜像和日志。

## 阶段 1：交易与食品安全 P0

**2026-09-07 至 2026-09-18**

- 支付、支付回调、退款和对账领域模型。
- 订单支付状态机和幂等回调。
- 商家资质审核、食品批次、食品安全事件和召回 API。
- Kubernetes 独立数据库迁移 Job。
- 商家端真实展示资质和食品安全记录。

验收：

- 重复支付通知不会重复记账。
- 重复退款请求不会重复退款。
- 每个订单可追溯到生产批次。
- 食品安全事件可以冻结餐品和订单。
- 迁移 Job 完成后 API 才能发布。

## 阶段 2：真实微信链路

**2026-09-21 至 2026-10-02**

- 接入真实 `wx.login` / `code2Session`。
- 接入微信支付沙箱或商户测试环境。
- 消费者、商家、骑手真机联调。
- 补充隐私政策、用户协议、商家诚信协议和食品安全协议。

验收：

- 真机登录、退出、重新登录和封禁流程通过。
- 支付成功、失败、超时、取消、退款全部可回放。
- 小程序 request 合法域名和 HTTPS 校验通过。

## 阶段 3：可观测性与容量

**2026-10-05 至 2026-10-16**

- Prometheus 指标、OpenTelemetry trace、集中日志。
- API、数据库、Redis、消息队列告警。
- 1,000、10,000、100,000 并发分级压测。
- 数据库连接池、Redis 热点、消息堆积和 Pod 重启演练。

验收：

- 关键接口有 p50/p95/p99 指标。
- 错误率、延迟、数据库连接耗尽有告警。
- 压测结果达到预设 SLO。
- 压测不能造成重复订单或数据丢失。

## 阶段 4：安全与灾备

**2026-10-19 至 2026-10-23**

- 安全扫描、依赖漏洞扫描和权限审计。
- PostgreSQL 备份恢复演练。
- Redis 故障和消息重放演练。
- 密钥轮换、回滚和应急联系人演练。

验收：

- 明确 RPO/RTO。
- 能从备份恢复订单和食品安全数据。
- 能在单个 API、Redis 或数据库节点故障时继续服务或可控降级。

## 阶段 5：灰度上线

**2026-10-26 至 2026-10-30**

- 一个园区或社区。
- 三到五家已核验商家。
- 五十到一百名种子用户。
- 固定一个配送时段。
- 人工客服和食品安全值守。

正式放量前必须满足：支付、资质、食品安全、备份恢复、监控告警和压测全部通过。

## 上线决策

- 任一 P0 验收失败：禁止公开上线。
- 支付或食品安全数据无法追溯：禁止下单。
- 数据库恢复演练失败：禁止扩大流量。
- 压测未达到 SLO：只允许封闭测试。
